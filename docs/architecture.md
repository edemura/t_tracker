# Архитектура и объем первой версии

## Назначение

Отслеживать задачи по направлениям: какие задачи есть, кто отвечает, какой статус и срок. Предполагается один пользователь в одном браузере, без авторизации.

## Слои

1. `index.html` и `styles.css`: представление, форма и адаптация.
2. `app.js`: состояние, события, отображение и сообщения об ошибках.
3. `tasks.js`: правила предметной области; не зависит от DOM и хранилища.
4. `storage.js`: загрузка и сохранение JSON. При подключении сервера этот слой можно заменить API-клиентом; асинхронный доступ потребует адаптации вызывающего кода.
5. `serve.mjs`: только локальная раздача файлов `public/`; задачи не принимает.

Сборка и внешние библиотеки отсутствуют. Исходники разделены для удобства изменений. Если потребуется сдача одним HTML-файлом, упаковку можно добавить отдельным этапом.

## Формат хранения

Ключ: `taskTracker.data`.

```json
{
  "schemaVersion": 1,
  "directions": [
    { "id": "automation", "name": "Автоматизация" },
    { "id": "operations", "name": "Операционная эффективность" },
    { "id": "process-analysis", "name": "Процессный анализ" }
  ],
  "tasks": [
    {
      "id": "a600a40b-ea5b-44c6-a700-3f9fdf846157",
      "title": "Автоматизировать еженедельный отчет",
      "description": "Согласовать состав показателей",
      "directionId": "automation",
      "status": "in_progress",
      "assignee": "Иван Петров",
      "dueDate": "2026-11-10",
      "createdAt": "2026-11-02T10:00:00.000Z",
      "updatedAt": "2026-11-02T10:00:00.000Z"
    }
  ]
}
```

Новые задачи получают UUID через `crypto.randomUUID()`. Импорт допускает любые непустые уникальные строковые ID для совместимости. Название (до 200 символов), ответственный (до 120), направление, статус и срок обязательны. Описание — строка до 5000 символов, допускается пустая. Статусы: `new`, `in_progress`, `done`, `cancelled`.

Срок — календарная дата `YYYY-MM-DD`. Технические отметки времени — UTC в ISO 8601. Просрочка вычисляется, а не хранится: срок раньше текущей локальной даты и статус не `done` / `cancelled`. Срок сегодня не считается просроченным. Отображение обновляется при возврате фокуса на страницу и раз в минуту.

При каждом изменении сначала проверяется модель, затем записывается весь документ и только после успешной записи обновляется состояние. Перед записью приложение перечитывает хранилище и при обнаружении изменений другой вкладки просит повторить действие. Это снижает риск перезаписи, но не является транзакционной блокировкой. Импорт — явная полная замена после подтверждения. Неизвестная версия схемы отклоняется, миграций пока нет.

Пользовательские данные выводятся как текст через DOM API, без вставки HTML. Сервер слушает только loopback-адрес. Авторизации и шифрования хранилища нет; приложение рассчитано на локальные рабочие задачи.

## Этапы и исходная оценка

| Этап | Трудозатраты |
| --- | --- |
| Поля, статусы, правила | 0,5–1 ч |
| Таблица, форма, адаптация | 1–2 ч |
| CRUD, валидация, хранение | 2–3 ч |
| Фильтры, сортировка, просрочка | 1–1,5 ч |
| Проверка и доработка | 1–1,5 ч |
| Документация и подготовка | 0,5–1 ч |
| Всего | 6–10 ч |

Это исходная оценка объема, а не отчет о фактически затраченном времени. Первая реализация подготовлена к пользовательскому просмотру. Следующий этап — обратная связь после запуска и согласование изменений.

## За рамками

Совместная работа между устройствами, учетные записи, уведомления, история, вложения, управление справочниками через интерфейс и упаковка в один HTML. Если понадобится общий список, добавить API и базу данных, отдельно определить доступ и правила конфликтов.
